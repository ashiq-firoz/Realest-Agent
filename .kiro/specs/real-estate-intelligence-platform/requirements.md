# Requirements: Real Estate Intelligence Platform

## Overview

Cotality Intelligence is an AI-powered real estate intelligence platform targeting the Australian property market. It transforms raw data from public APIs (Domain, ABS, data.gov.au, Nominatim) into professional-grade market reports generated by Google Gemini. The platform supports two user tiers (Regular and Pro) and is built on a Next.js 14 frontend backed by a FastAPI Python service with PostgreSQL, Redis, and Docker infrastructure.

The existing codebase is a working MVP with: Next.js 14 (App Router), SQLite/Prisma, hardcoded mock data, Gemini API integration, no authentication, and no caching. This upgrade replaces SQLite with PostgreSQL, adds FastAPI as the data/AI backend, introduces NextAuth.js authentication (Google OAuth + Email/Password), Redis caching, Australian data sources, PDF export via WeasyPrint, shareable report links, Pro tier features, and a market watchlist/saved-locations dashboard.

## Requirement 1: Location Search & Autocomplete

**User Story:** As a user, I want to search for Australian locations using autocomplete, so that I can quickly find and select a specific country/state/city/neighbourhood for analysis.

### Acceptance Criteria

1. WHEN a user types at least 2 characters into the location search input THEN the system SHALL query the Nominatim geocoding API and return up to 8 matching Australian location suggestions within 500 ms
2. WHEN a user selects a location from the autocomplete dropdown THEN the system SHALL store the resolved coordinates (lat/lon), display name, suburb/city, state, and country for use in report generation
3. WHEN the Nominatim API is unavailable THEN the system SHALL display a user-friendly error and allow manual text entry as fallback
4. WHEN a user submits a location THEN the system SHALL validate that the resolved location is within Australia before proceeding

## Requirement 2: Authentication

**User Story:** As a user, I want to sign in with Google or Email/Password, so that my reports and settings are saved to my account.

### Acceptance Criteria

1. WHEN a user signs in with a Google account via OAuth THEN the system SHALL create or retrieve a user record and issue a JWT token valid for 24 hours
2. WHEN a user registers with email and password THEN the system SHALL hash the password with bcrypt (cost ≥ 12), store the user record, and issue a JWT token valid for 24 hours
3. WHEN a user submits an invalid email or a password shorter than 8 characters THEN the system SHALL reject the request with a descriptive validation error
4. WHEN an authenticated request is made to the FastAPI backend THEN the system SHALL validate the JWT and attach the user identity to the request context
5. WHEN a JWT token expires THEN the system SHALL redirect the user to the login page and preserve the originally requested URL as a redirect parameter
6. WHEN a user logs out THEN the system SHALL invalidate the session and clear auth cookies

## Requirement 3: AI Report Generation

**User Story:** As a user, I want to generate a comprehensive real estate intelligence report for any Australian location, so that I can make informed property decisions.

### Acceptance Criteria

1. WHEN a user initiates a report generation for a location THEN the system SHALL fetch data from Domain API, ABS API, data.gov.au, and Nominatim in parallel, falling back to cached or mock data for unavailable sources
2. WHEN all data is aggregated THEN the system SHALL send a structured prompt to the Gemini gemini-1.5-pro model and receive a markdown-formatted report covering: Market Overview, Neighbourhood Insights, Demographics, Investment Intelligence, Comparable Properties, and AI Summary
3. WHEN Gemini returns the response THEN the system SHALL parse and store the 6 report sections individually in the reports table
4. WHEN a report is saved THEN the system SHALL generate a unique short token (8 characters, URL-safe) and store it alongside the report for shareable link use
5. WHEN a user requests the same location within the Redis cache TTL (configurable, default 6 hours) THEN the system SHALL serve the aggregated data from Redis without calling external APIs again
6. WHEN report generation takes longer than 30 seconds THEN the system SHALL return a timeout error and surface a user-friendly retry message
7. WHEN the Gemini API returns an error THEN the system SHALL log the error and return a partial report with all non-AI sections populated and an AI Summary placeholder

## Requirement 4: Report Viewing

**User Story:** As a user, I want to view a detailed formatted report, so that I can read all market insights in one place.

### Acceptance Criteria

1. WHEN a user navigates to a report URL THEN the system SHALL display all 6 sections: Market Overview, Neighbourhood Insights, Demographics, Investment Intelligence, Comparable Properties, and AI Summary
2. WHEN a report is displayed THEN the system SHALL render key metrics (median price, price appreciation, rental yield, days-on-market, ROI estimate) as prominently styled stat cards
3. WHEN a report is displayed THEN the system SHALL render Comparable Properties as a sortable table with address, price, beds, baths, sqft, and listing type columns
4. WHEN a user clicks "Share" THEN the system SHALL copy the shareable public link (`/share/{token}`) to the clipboard and show a confirmation toast
5. WHEN an unauthenticated user opens a shareable link THEN the system SHALL render the full report without requiring login
6. WHEN a user views a report they do not own THEN the system SHALL display the report in read-only mode without edit or delete controls

---

## Requirement 5: PDF Export

**User Story:** As a user, I want to export a report as a PDF, so that I can share it offline or archive it.

### Acceptance Criteria

1. WHEN a user clicks "Export PDF" THEN the system SHALL call the FastAPI `/reports/{id}/export/pdf` endpoint and stream a PDF file to the browser
2. WHEN the PDF is generated THEN it SHALL include all 6 report sections, the Cotality Intelligence branding header, the location name, and the generation date
3. WHEN PDF generation fails THEN the system SHALL surface an error toast and log the exception server-side
4. WHEN an unauthenticated user attempts PDF export THEN the system SHALL redirect to login

## Requirement 6: Dashboard — Regular Tier

**User Story:** As a Regular user, I want a dashboard showing my recent reports, so that I can revisit past analyses quickly.

### Acceptance Criteria

1. WHEN a Regular user visits the dashboard THEN the system SHALL display their last 20 reports ordered by creation date descending, with location name, generation date, median price, and a link to the full report
2. WHEN a user has no reports THEN the system SHALL display an empty-state prompt encouraging the first analysis
3. WHEN a user clicks a report card THEN the system SHALL navigate to the full report page
4. WHEN a user deletes a report THEN the system SHALL soft-delete the record and remove it from the dashboard immediately without page reload

---

## Requirement 7: Dashboard — Pro Tier

**User Story:** As a Pro user, I want advanced dashboard features including market watchlist, saved locations, and investment analytics, so that I can track markets I care about over time.

### Acceptance Criteria

1. WHEN a Pro user visits the dashboard THEN the system SHALL display all Regular dashboard features plus: Saved Locations panel, Market Watchlist panel, and Investment Analytics summary
2. WHEN a Pro user saves a location THEN the system SHALL store it in the `saved_locations` table and display it in the Saved Locations panel with a one-click "Generate Report" button
3. WHEN a Pro user adds a location to the Market Watchlist THEN the system SHALL store a watchlist entry and display median price trend sparklines for the last 12 available data points
4. WHEN a Pro user views Investment Analytics THEN the system SHALL aggregate ROI estimates and rental yields across their saved locations and display a ranked comparison table
5. WHEN a Regular user attempts to access a Pro feature THEN the system SHALL display an upgrade prompt modal instead of the feature content

---

## Requirement 8: Advanced Filters & Comparable Properties (Pro)

**User Story:** As a Pro user, I want to filter comparable properties by type, price range, beds, and baths, so that I can narrow down comps to my specific investment criteria.

### Acceptance Criteria

1. WHEN a Pro user views the Comparable Properties section THEN the system SHALL display filter controls for: property type (house/unit/townhouse), price range (min/max), bedrooms (min), bathrooms (min)
2. WHEN a Pro user applies filters THEN the system SHALL re-query the comparables dataset client-side and update the table without a full page reload
3. WHEN filter values are outside the available data range THEN the system SHALL display a "No matching properties" message
4. WHEN a Regular user views Comparable Properties THEN the system SHALL show the default unfiltered table only, with a Pro upgrade prompt adjacent to the filter controls area

---

## Requirement 9: Data Aggregation Pipeline

**User Story:** As the platform, I want to pre-aggregate property data from Australian APIs on a schedule, so that report generation is fast and resilient to API outages.

### Acceptance Criteria

1. WHEN the data pipeline runs THEN the system SHALL call Domain API, ABS API, and data.gov.au endpoints per suburb/postcode and store results in the `aggregated_market_data` table
2. WHEN an external API call fails THEN the system SHALL log the failure, mark the affected data record as stale, and continue with other sources
3. WHEN cached aggregated data exists for a location THEN the system SHALL serve it from Redis if within TTL, otherwise re-fetch from PostgreSQL
4. WHEN Domain API returns property listings THEN the system SHALL normalize the data into a canonical `PropertyListing` schema before storage
5. WHEN ABS API returns demographic data THEN the system SHALL normalize it into the `DemographicsSnapshot` schema

## Requirement 10: Infrastructure & Configuration

**User Story:** As a developer, I want a Docker Compose environment with all services, so that I can run the full platform locally with a single command.

### Acceptance Criteria

1. WHEN `docker-compose up` is run THEN the system SHALL start: PostgreSQL 15, Redis 7, FastAPI service, and Next.js service, all on a shared internal network
2. WHEN services start THEN the FastAPI service SHALL run database migrations automatically via Alembic before accepting requests
3. WHEN environment variables are missing THEN the services SHALL fail fast with a clear startup error identifying the missing variable
4. WHEN the FastAPI service receives a request THEN it SHALL validate the JWT from the `Authorization: Bearer` header for all protected endpoints
5. THE Docker Compose file SHALL use named volumes for PostgreSQL and Redis data persistence across container restarts

---

## Requirement 11: Report Section Quality & Prompt Engineering

**User Story:** As a user, I want the AI-generated report sections to be professional, data-grounded, and structured, so that I can trust the insights for decision-making.

### Acceptance Criteria

1. WHEN constructing the Gemini prompt THEN the system SHALL inject all available structured data (market stats, demographics, comparables) as a JSON context block and instruct the model to reference specific data points
2. WHEN the Gemini response is received THEN the system SHALL validate that all 6 required sections are present; if any are missing the system SHALL re-prompt once with a correction instruction
3. WHEN the AI Summary section is generated THEN it SHALL include: Market Summary, Investment Recommendation, Risk Indicators, and Opportunities sub-sections in Markdown format
4. WHEN rendering AI-generated markdown THEN the system SHALL use a proper markdown renderer (react-markdown or equivalent) rather than manual string splitting
